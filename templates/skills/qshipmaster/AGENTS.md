# qshipmaster — Cross-Epic Learnings (AGENTS.md)

This file is procedural memory across qshipmaster runs. Each entry records a
wave-level Phase 2 failure that required a fix-worker iteration, so future
epic orchestration can avoid repeating the same root causes.

Pattern source: ralph-zero (https://github.com/davidkimai/ralph-zero) —
mandatory `AGENTS.md` documentation injected into each fresh agent session.

`qship-persist.sh` reads this file and folds the most recent ~15 entries into
its autonomy directive, so workers see prior pitfalls before running.

{{JIRA_PROJECT_KEY}}-EX06-macos-tcc-stall-root-cause  / ROOT_CAUSE: macOS TCC (Transparency Consent Control) permission popups silently stall qshipmaster subprocesses. When claude --print spawned by qshipmaster invokes Playwright/Chromium or chrome-devtools-attach, macOS sometimes fires a permission dialog (Accessibility, Screen Recording, Automation, Files-and-Folders). The dialog appears in the host process tree (Claude.app/Contents/Helpers/disclaimer) — NOT in the subprocess — so the subprocess can never see or answer it. Playwright/Chrome blocks indefinitely on the underlying system call; stream-json log produces zero output; heartbeat file never updates (claude is frozen pre-heartbeat-touch); supervisor SIGTERMs after 30+ min thinking it's hung, never knowing TCC was the cause. Confirmed against the disclaimer-wrapper architecture documented in anthropics/claude-code#36832 ("TCC entry doesn't persist reliably across sessions for this process hierarchy") and #23550 ("Xcode MCP tools requiring Automation permission hang indefinitely for CLI clients without bundle identifiers"). / FIX: (1) Created qshipmaster-tcc-preflight.sh — minimal Playwright launch with 30s timeout BEFORE any subprocess work. Detects the stall pattern fast and fails-fast with concrete remediation: System Settings paths, tccutil reset commands, Claude.app bundle ID com.anthropic.claudefordesktop, chrome-devtools-attach alternative. Wired into qshipmaster-run.sh at startup (after Chrome auto-launch, before MAX_WAVE_ITERS defaults). Skip via QSHIP_SKIP_TCC_PREFLIGHT=true for headless CI. (2) Updated AGENTS.md with the stall signature so supervisor self-prompts learn to recognize it: "subprocess pcpu=0 + heartbeat absent + log frozen + Playwright/Chrome MCP in tool stack = likely TCC, not actual hang". / RULE: ANY Claude Code subprocess that touches Playwright, Chromium, /qmanualt, /qe2etest, or chrome-devtools-attach MUST run a pre-flight TCC check or have an explicit user-confirmed grant first. There is no programmatic tccutil --insert without SIP disabled; one-time UI grant via System Settings is the only safe path. Default to chrome-devtools-attach (Chrome at :9222) over fresh Playwright Chromium because the user's interactive Chrome holds STABLE TCC grants the disclaimer wrapper never sees.
